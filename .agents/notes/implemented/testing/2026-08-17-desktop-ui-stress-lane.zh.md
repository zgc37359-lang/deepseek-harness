# Agent Note：桌面 UI 压力通道与扩展矩阵

Status: implemented

[English](2026-08-17-desktop-ui-stress-lane.md) | 中文

## 问题

桌面 UI 矩阵覆盖了核心链路（窗口控制、会话创建/切换、预设、模式、模型选择、
文本与工具发送、设置、复制、会话日志），但没有覆盖完整交互面，也没有自动化通道
去压测真实队列、大输出和快速重复操作。“所有按钮都能点”这类回归只能靠手工发现。

## 决策

`apps/desktop/scripts/ui-matrix.mjs` 从 31 步扩到 60 步：

- Shell：最小化/还原、关闭到托盘。
- 侧边栏：收起/展开 rail、展开折叠会话、视图选项（按工作区/单列/手动/最近）、
  工作区行菜单、会话行重命名应用/还原、会话分叉、工作区新建。
- Composer：命令面板、`/goal`、发送按钮、上下文仪表。
- 设置：主题浅色/深色/跟随系统、默认权限预设、提供方编辑、插件列表、
  预设查看/复制。
- 对话：消息反馈（赞/踩+备注）、详情面板、轨迹筛选/搜索。

`apps/desktop/scripts/stress-test.mjs` 是新门禁：四条排队连发、120 行大输出、
五次快速会话操作、活跃窗口事件循环抖动采样、主进程内存增量，带失败预算
（p95 抖动 ≤ 200 ms、内存增量 ≤ 700 MiB、零 console/page 错误）。

## 验证

- 扩展矩阵：60 步全部通过（未分组会话的界面显式跳过而非误报；先种一条真实
  消息再跑发送与对话步骤）。
- 压力通道：连发 4/4 完成、120/120 行约 16 秒、快速点击每次约 20 ms、
  事件循环 p95 30 ms、内存增量 49 MiB、零错误。
- 重建包上的既有性能门禁：冷启动 2.1 秒 / 288 MiB；事件循环 p95 31.6 ms /
  120 FPS；流式首 token 约 1.7 秒、吞吐 122 字符/秒（一次瞬时 91 字符/秒，
  复跑通过）。

## 备选方案

**等待每次“新建会话”点击都产生新 id。** 运行时会按设计复用目标工作区已有的
空白会话，因此矩阵现在接受“新建或复用”，并通过轮次增量定位真实活动会话。

## 影响

UI 矩阵与压力通道可本地运行，也能加入 Windows 桌面工作流。矩阵容忍应用重启后
落在空白分叉会话上：先种入内容再执行 hero 相关步骤。
